Gitea exposes the source address of imported repositories as `original_url` in its repository API. Extend the existing credential removal contract so these public addresses also omit query parameters named `token`, `access_token`, or `password`. Match parameter names case-insensitively after URL decoding and remove every occurrence, including repeated or mixed-case names.

For example, an imported address `https://alice:secret@git.example/project?branch=main&ToKeN=private&branch=release#readme` must expose no user information or token, while retaining the two branch values and the fragment. Parameters with other names such as `tokenizer` and `oauth_token_hint` remain present. Preserve the meaning of noncredential values and paths, including escaped characters. Addresses without credential query parameters keep their query spelling and order. Malformed URL/query escapes must return an error and produce an empty sanitized address rather than exposing a partially sanitized value. Keep the existing behavior for empty source addresses and ordinary URLs.

Apply this behavior throughout the repository metadata exposure path. Do not alter the stored original address or credentials used for contacting the remote. This is a new controlled requirement, not a claim about a historical Gitea issue.
